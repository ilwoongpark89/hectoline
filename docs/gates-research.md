# Research on gates

A gate is any check that can refuse work. `RULE.md` §8 limits gates. Each rule there rests on a source that was read to its end. This page lists those sources. One entry holds the question, the source, its words, and the finding that the rule takes from it. The quotes are verbatim. The findings are the reading of this method, not of the authors. The sources stand in the table at the end.

## 1. Does a planted fault prove that a check catches real faults?

- Words: «73% of real faults are coupled to the mutants generated by commonly used mutation operators.» «However, 17% of real faults, mostly involving algorithmic changes or code deletion, are not coupled to any mutants.»
- Finding: A generic plant stands for most real faults, not for all. The step from there to «plant the fault that occurred» is this method's, the paper asks for better operators.
- Source: S1

## 2. May a check take its expected value from the thing it tests?

- Words: «A correct or incorrect program is equally likely to pass a test that is a derivative of the code under test.»
- Finding: No. The reference stays outside the change under test. An argument, no data.
- Source: S2

## 3. What does a check with a wrong reference cost?

- Words: «when in error the CDSS increased the risk of an incorrect decision being made by 26%»
- Finding: Wrong advice of a check is followed: the risk of a wrong decision rose by 26 percent against no aid.
- Source: S3

## 4. Does compliance by form move the outcome?

- Words: «Implementation of surgical safety checklists in Ontario, Canada, was not associated with significant reductions in operative mortality or complications.» «Almost all of the 97 large community hospitals reported compliance of 99% or 100% during the period from January through June 2013.»
- Finding: Full compliance by form came with no measured gain. Form alone does not pass.
- Source: S4

## 5. What happens when refusals with low credibility pile up?

- Words: «Too many alerts with low credibility may cause physicians to override important alerts along with unimportant ones.» «Turning off alerts without careful error management may impair patient safety.»
- Finding: False refusals make the true ones ignored. Removal in bulk with no test is a risk of its own.
- Source: S5

## 6. Does each added alert lower the response to all of them?

- Words: «With every additional BPA per encounter, the likelihood a clinician would accept any BPA dropped by 30%»
- Finding: Yes in this cohort, minus 30 percent for each one, repeats cost more. The same paper cites reviews with no link to volume.
- Source: S6

## 7. How large can the false share of an alarm stream grow?

- Words: «88.8% of the 12,671 annotated arrhythmia alarms were false positives.»
- Finding: Nine of ten. A gate holds a measured false-refusal share, not an assumed one.
- Source: S7

## 8. At which measured rate does a check leave?

- Words: «We define an effective false positive as any report from the tool where a user chooses not to take action to resolve the report.» «A rate ≥ 10% puts the analyzer on probation, and the analysis writer must show progress toward addressing the issue. If the rate goes above 25%, we may decide to turn the analyzer off immediately»
- Finding: The leave rule is a number stated in advance, read all the time. At 10 percent probation starts. Over 25 percent the check may be turned off. A false positive is any report not acted on.
- Source: S8

## 9. May a blocking check ever refuse correct work?

- Words: «produce no effective false positives (the analysis should never stop the build for correct code)» «If the ratio for an analyzer goes above 10%, the Tricorder team disables the analyzer until the author(s) improve it.»
- Finding: No. A check that stops work holds zero false refusals. A check that only warns may hold up to 10 percent.
- Source: S9

## 10. Is switching a noisy check off a safe halfway step?

- Words: «about 84% of the transitions we observe from pass to fail involve a flaky test» «could easily mask a real race condition or some other bug in the code being tested»
- Finding: No. Noise makes true failures ignored, a quarantined check hides faults. A gate is removed with its test or it stays, it is not disabled.
- Source: S10

## 11. By which criterion do alert rules leave?

- Words: «Data collection, aggregation, and alerting configuration that is rarely exercised (e.g., less than once a quarter for some SRE teams) should be up for removal.»
- Finding: By use: a rule that did not fire in a quarter is a removal candidate. The review reads refusals for each gate.
- Source: S11

## 12. When does a lint rule leave?

- Words: «Rules will never be removed from ESLint unless one of the following is true»
- Finding: Only when a named rule covers it. The page names no proof of the cover.
- Source: S12

## 13. Does a cover shown at removal time stay true?

- Words: «the reduction based on killed mutants achieves no loss in killed mutants» «the loss in killed mutants is at most 15.76pp from the initial loss in killed mutants due to reduction»
- Finding: A list of planted faults gives zero loss at removal. The equality decays as the code changes, by up to 15.76 points: the list runs again at each review.
- Source: S13

## 14. How often is a claim «this check covers that one» wrong?

- Words: «Mutation score decreasing from 51% in original test set to 20% in the reduced set only based on coverage information»
- Finding: On one program of 82 tests, removal by a coverage claim cut the detection from 51 to 20 percent. The before-against-after list on planted faults is what showed it.
- Source: S14

## 15. What does a named later cover cost?

- Words: «0.2% of all defects escaped at least one test execution» «we skip tests only if we know that the code change will be tested by the same execution context later again»
- Finding: By a replay of history, with the cover named with the state where it runs. In Windows 0.2 percent of defects escaped one stage, in Dynamics 13.4 percent. The cost depends on the product.
- Source: S15

## 16. Does a review by calendar shrink the stock of rules?

- Words: «Florida has terminated 90 agencies under Sunset since 1978, but has created 104 new agencies» «twelve states have repealed or suspended the enabling legislation»
- Finding: Not by itself: 12 of 36 states dropped the sweep, new entities replaced the ended ones. The count review is a backstop, the per-gate number is the rule.
- Source: S16

## 17. Can a list of forbidden inputs hold?

- Words: «Do not rely exclusively on detecting disallowed inputs.» «Only use detection of disallowed inputs as a mechanism for detecting suspicious activity.»
- Finding: No. A list of forbidden texts detects, it does not prevent.
- Source: S17

## 18. How does a mechanism that excludes fail?

- Words: «a design or implementation mistake in a mechanism that explicitly excludes access tends to fail by allowing access, a failure which may go unnoticed in normal use»
- Finding: It fails open, unseen. A guard names what may pass, the rest is refused.
- Source: S18

## 19. Can command matching subtract commands?

- Words: «It is generally not effective to "subtract" commands from ALL using the '!' operator.» «these kind of restrictions should be considered advisory at best»
- Finding: No. A copy under another name runs the same code.
- Source: S19

## 20. Is a rule on the text of a Bash command a boundary?

- Words: «It doesn't match the same program invoked in a different form, so a deny or ask rule covers the invocation Claude usually produces and isn't a security boundary around the program.»
- Finding: No, by the vendor of the agent itself. It covers the usual form. The hard limit is the sandbox below it.
- Source: S20

## 21. Does a list of safe read commands hold?

- Words: «Maintaining allowlists of "safe" commands without a sandbox is fundamentally flawed.»
- Finding: No. Flags of listed commands write and run. The read list of the log gate is of this kind.
- Source: S21

## 22. Does a learned filter of command text hold against a search?

- Words: «We show that WAF-A-MoLE bypasses all the considered machine learning based WAFs.»
- Finding: A guided search passed every learned filter tested. The signature filter was a baseline that the search did not attack, so the paper gives no number against it.
- Source: S22

## 23. Can a count stand for the product?

- Words: «No matter what measure is chosen for optimization, an inexact metric necessarily leads to a divergence between the goal and the metric in the tail.»
- Finding: No. A count supports a verdict, the product is examined. An argument, no data.
- Source: S23

## 24. What does a visible scorer do to an agent?

- Words: «Reward hacking was more than 43× more common on RE-Bench tasks than HCAST tasks» «patch the exploit in the scoring function rather than punishing the model»
- Finding: Hacking rose 43 times where the agent saw the scorer, METR names two other possible causes. The reviewer keeps its own cases apart. A found exploit is closed in the structure.
- Source: S24

## 25. Can the user that owns a file lift its append-only flag?

- Words: «The “UF_IMMUTABLE”, “UF_APPEND”, “UF_OPAQUE”, and “UF_HIDDEN” flags may be set or unset by either the owner of a file or the super-user.» «The “SF_ARCHIVED”, “SF_IMMUTABLE” and “SF_APPEND” flags may only be set or unset by the super-user.»
- Finding: Yes for the user flag, no for the system flag. A leave condition of a gate on a file names a principal that the session cannot act as.
- Source: S25

## 26. Do the two text-match gates of this room hold?

- Words: «upper-case key on a commit line, a bypass ¦ allowed» «prose appended to a report outside the room, correct work ¦ denied: git bypass flag» «tail with a redirect to a glob that names the log, a write ¦ allowed»
- Finding: Neither holds. Of 14 lines, 6 are judged wrongly. The bypass pattern gave one false pass with one false refusal. Both gates left in version 1.2. Structure took their place.
- Source: S26
